# 造血干细胞捐献协同

本项目支撑非血缘造血干细胞捐献的候选检索、志愿者联络、体检、采集与运输。患者和志愿者使用不同身份域，业务流程只出现不可反查的别名；紧急身份解封由两名授权人员确认并设置自动到期时间。

候选记录包含分型匹配、算法版本、排除理由、同意范围和冷静期。确认捐献后，由采集医院、移植医院和运输方共同上报里程碑。样例事件涵盖航班延误、体检异常、志愿者撤回和候选替补。

## 领域模块（coordination/）

- `identity.py` — 身份保险库：身份密钥与业务数据分离，业务侧只用 HMAC 别名；紧急解封需双人批准（请求人不能自批），令牌自动到期，每次反查留审计。
- `consent.py` — 同意范围与冷静期：每次联络/体检/采集以最新同意为准，冷静期内禁止联络。
- `matching.py` — 患者检索与候选排序：患者侧只提交分型与临床时限；候选记录固定算法版本并保留排除理由。
- `cases.py` — 个案流程：一名志愿者同一时间只允许一个有效承诺，个案视图不泄露其他个案；联络通知按幂等键去重，重试不重复通知。
- `logistics.py` — 采集排程与里程碑：同案排程幂等、同人不得重复采集；采集医院/移植医院/运输方围绕有效时间窗上报，跨时区时刻统一归一 UTC。
- `disruptions.py` — 航班延误、体检异常、志愿者撤回触发有优先级的替代方案与候选替补。
- `audit.py` — 仅追加审计日志，导出中只含别名，供逐条核对匹配、替补与解封依据。

## 运行与验证

- `python3 service.py --check` — 基础检查（含领域模块导入）。
- `python3 service.py --port 8000` — 启动健康探针。
- `npm test` — 运行服务契约测试与全部领域测试。

## 联调场景（tests/test_joint_flow.py）

同时推进两个患者流程：个案一锁定最高分志愿者后，该志愿者在个案二中自动进入排除名单（理由 `committed_elsewhere`，不泄露个案一信息）；个案二锁定的志愿者撤回后按候选顺序自动替补。随后注入跨时区航班延误（北京时间的计划、美东时间的上报），生成有优先级的替代方案并调整有效时间窗。全程验证联络重试与采集排程重试不产生重复通知或重复采集，紧急解封经双人批准并自动到期，最后从审计导出中逐条核对每次匹配、替补与解封的依据。
